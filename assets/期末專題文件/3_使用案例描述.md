# 三、使用案例描述（情節）（參考第六章）

> 每個使用案例提供一張**正常情節**與一張以上的**例外情節**。
> 表格左欄為 Actor 動作，右欄為系統回應；步驟以數字標示。
> **TUCBW** = The Use Case Begins With（使用案例開始於）；**TUCEW** = The Use Case Ends With（使用案例結束於）。

---

## UC-1 查證內容（文字／網址）

| 項目 | 內容 |
|------|------|
| 使用案例名稱 | 查證內容（文字／網址） |
| 案例簡述 | 使用者提交一段文字或網址，系統判定其為詐騙／假訊息／安全並附佐證 |
| 參與角色 | 使用者、AI 引擎 |
| 前提 | 系統正常運作；AI 引擎金鑰有效 |
| 成功條件 | 系統回傳風險類型、摘要、解釋與佐證來源 |

### 情節 1-A：正常情節（快取未命中，AI 判定成功）

| 步驟 | Actor 動作（使用者） | 系統回應 |
|:--:|----------------------|----------|
| 1 | **TUCBW：** 使用者貼上可疑訊息並按「發布查證」 | |
| 2 | | 系統建立查證任務並回傳 task_id |
| 3 | | 系統以 Layer 0/1/2 比對三層快取（皆未命中） |
| 4 | | 系統呼叫 AI 引擎分析內容 |
| 5 | | AI 引擎回傳風險類型、摘要、解釋與佐證來源 |
| 6 | | 系統將結果回填知識庫並更新任務為「完成」 |
| 7 | 使用者輪詢任務結果 | 系統回傳查證結果卡片 |
| 8 | | **TUCEW：** 系統顯示風險類型與佐證來源 |

### 情節 1-B：例外情節（快取命中）

| 步驟 | Actor 動作（使用者） | 系統回應 |
|:--:|----------------------|----------|
| 1 | **TUCBW：** 使用者送出與先前相同／相似的內容 | |
| 2 | | 系統於三層快取中命中既有結果 |
| 3 | | **TUCEW：** 系統直接回傳快取結果（標記 cached），不呼叫 AI |

### 情節 1-C：例外情節（AI 限流或失敗）

| 步驟 | Actor 動作（使用者） | 系統回應 |
|:--:|----------------------|----------|
| 1 | **TUCBW：** 使用者送出查證請求 | |
| 2 | | 三層快取未命中，系統呼叫主 AI 引擎 |
| 3 | | 主引擎逾時／限流，系統自動改用備援引擎 |
| 4 | | 備援仍失敗 |
| 5 | | **TUCEW：** 系統回傳「AI 分析暫時無法使用」之提示，任務標記失敗 |

## UC-2 查證圖片

| 項目 | 內容 |
|------|------|
| 使用案例名稱 | 查證圖片 |
| 案例簡述 | 使用者上傳圖片，系統做 OCR 與視覺分析後判定真偽 |
| 參與角色 | 使用者、AI 引擎 |
| 前提 | 圖片格式為 PNG/JPG/WEBP 且小於 10MB |
| 成功條件 | 系統回傳對圖片內容的查證結果 |

### 情節 2-A：正常情節

| 步驟 | Actor 動作（使用者） | 系統回應 |
|:--:|----------------------|----------|
| 1 | **TUCBW：** 使用者上傳圖片並送出 | |
| 2 | | 系統暫存圖片並建立查證任務 |
| 3 | | 系統呼叫 AI 引擎進行 OCR 與視覺判讀 |
| 4 | | AI 引擎回傳風險類型與解釋 |
| 5 | | 系統刪除暫存圖片 |
| 6 | | **TUCEW：** 系統顯示查證結果 |

### 情節 2-B：例外情節（非圖片或檔案過大）

| 步驟 | Actor 動作（使用者） | 系統回應 |
|:--:|----------------------|----------|
| 1 | **TUCBW：** 使用者選擇了非圖片檔或大於 10MB 的檔案 | |
| 2 | | **TUCEW：** 系統顯示錯誤提示並要求重新選擇，不建立任務 |

## UC-3 查證影片

| 項目 | 內容 |
|------|------|
| 使用案例名稱 | 查證影片 |
| 案例簡述 | 使用者提交影片網址，系統取得逐字稿後判定影片內容真偽 |
| 參與角色 | 使用者、AI 引擎 |
| 前提 | 影片可公開存取 |
| 成功條件 | 系統依影片實際內容回傳查證結果 |

### 情節 3-A：正常情節（有字幕）

| 步驟 | Actor 動作（使用者） | 系統回應 |
|:--:|----------------------|----------|
| 1 | **TUCBW：** 使用者貼上影片網址並送出 | |
| 2 | | 系統取得影片字幕並整理成逐字稿 |
| 3 | | 系統將逐字稿送 AI 引擎判定 |
| 4 | | **TUCEW：** 系統顯示查證結果 |

### 情節 3-B：例外情節（無字幕，改用語音轉文字）

| 步驟 | Actor 動作（使用者） | 系統回應 |
|:--:|----------------------|----------|
| 1 | **TUCBW：** 使用者送出無字幕影片網址 | |
| 2 | | 系統發現影片無字幕，下載音軌 |
| 3 | | 系統呼叫語音轉文字（whisper）取得逐字稿 |
| 4 | | 系統將逐字稿送 AI 引擎判定 |
| 5 | | **TUCEW：** 系統顯示查證結果 |

## UC-5 更新今日熱門

| 項目 | 內容 |
|------|------|
| 使用案例名稱 | 更新今日熱門 |
| 案例簡述 | 使用者手動觸發系統抓取最新查核新聞 |
| 參與角色 | 使用者、管理員、查核來源 |
| 前提 | 系統可連線外部查核來源 |
| 成功條件 | 系統抓取並更新熱門列表 |

### 情節 5-A：正常情節

| 步驟 | Actor 動作（使用者） | 系統回應 |
|:--:|----------------------|----------|
| 1 | **TUCBW：** 使用者點擊「立即更新」 | |
| 2 | | 系統於背景抓取 RSS／Cofacts 查核文章 |
| 3 | | 系統分類來源並索引已查核假訊息 |
| 4 | 使用者輪詢列表 | 系統回傳更新後的熱門列表 |
| 5 | | **TUCEW：** 系統顯示最新熱門列表 |

### 情節 5-B：例外情節（來源無回應）

| 步驟 | Actor 動作（使用者） | 系統回應 |
|:--:|----------------------|----------|
| 1 | **TUCBW：** 使用者點擊更新 | |
| 2 | | 部分查核來源逾時無回應 |
| 3 | | 系統略過失敗來源，僅以可用來源更新 |
| 4 | | **TUCEW：** 系統顯示可取得的熱門列表 |

| 參與角色 | 使用者 |

## UC-7 自動抓取查核新聞（系統）

| 項目 | 內容 |
|------|------|
| 使用案例名稱 | 自動抓取查核新聞 |
| 案例簡述 | 排程器依時間自動蒐集查核新聞、分類並索引 |
| 參與角色 | 時間（排程器）、查核來源、AI 引擎 |
| 前提 | 已啟用排程（ENABLE_SCHEDULER） |
| 成功條件 | 系統更新熱門記錄並把已查核假訊息寫入知識庫 |

### 情節 7-A：正常情節

| 步驟 | Actor 動作（時間／排程器） | 系統回應 |
|:--:|----------------------|----------|
| 1 | **TUCBW：** 排程時間到，觸發抓取 | |
| 2 | | 系統抓取 RSS／Cofacts 查核文章 |
| 3 | | 系統依來源網域與查核標籤分類 |
| 4 | | 對「確定不實」者擷取原始謠言、向量化並索引 |
| 5 | | **TUCEW：** 系統更新熱門記錄與知識庫 |

### 情節 7-B：例外情節（AI 限流）

| 步驟 | Actor 動作（時間／排程器） | 系統回應 |
|:--:|----------------------|----------|
| 1 | **TUCBW：** 排程觸發，對未知來源呼叫 AI | |
| 2 | | AI 引擎回傳限流（429/503） |
| 3 | | 系統停止本輪 AI 分析，保留為未查證 |
| 4 | | **TUCEW：** 系統於下個週期再行重試 |
