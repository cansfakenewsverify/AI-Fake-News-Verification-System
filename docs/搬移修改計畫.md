# 修改計畫：把 `factcheck_system` 攤平進 `code/backend`

> 目標：`code/backend/factcheck_system/*` → `code/backend/*`（不要多一層 `factcheck_system` 資料夾）。
> 完成後在 `CLAUDE.md` 記錄此次搬移。**執行前需先確認第七節 3 個決策。**

## 一、現況發現（重要）
`code/backend/` 已有一批舊的重複/死檔，會與搬移衝突。git 追蹤的有：

| code/backend/ 既有（舊） | factcheck_system/ 內（在用） | 處理 |
|---|---|---|
| `main.py`（把 factcheck_system 加進 path 再 import app 的轉接墊片） | `app/main.py`（真正 FastAPI） | 攤平後多餘 → **刪** |
| `fix_models.py`、`test_invoke.py`（早期死腳本） | — | **刪** |
| `requirements.txt`（533B 舊版） | `requirements.txt`（980B，Py3.13 版） | factcheck 版**勝** |
| `data/knowledge_base.parquet`+`tasks.parquet`（舊） | `data/`（178 筆知識庫＋factcheck.db＋評測檔） | factcheck 版**勝** |
| `.gitignore`（backend 層級） | （無） | 保留 |
| `venv/`（舊） | `venv/`（在用） | **重建** |

factcheck_system 內另有沒人用的遺留物：內層 `factcheck_system/`（cli/crawler/services）、`factcheck_system.egg-info/`、`pyproject.toml`、`alembic.ini`、`migrations/`。

## 二、目標結構
```
code/backend/
├── app/  scripts/  data/  static/  tmp/
├── requirements.txt  .env  .env.example  README.md
├── _run_backend.bat  Dockerfile  docker-compose.yml
└── venv/（重建）
```

## 三、處理決策（建議）
1. 刪死檔：`code/backend/{main.py, fix_models.py, test_invoke.py}`、舊 `requirements.txt`、舊 `data/` 重複檔。
2. 衝突一律以 factcheck_system 版本為準（requirements、data、.env）。
3. 移除沒人用的安裝套件機制：內層 `factcheck_system/`、`egg-info`、`pyproject.toml`（這樣才真正不多一層）。連帶刪 README 第 197 行 `from factcheck_system import ...` 段。
4. `alembic.ini` + `migrations/`：用 SQLite 沒在跑，傾向保留（低風險），可選刪。

## 四、執行步驟
1. `git rm` 死檔/舊重複檔。
2. `git mv` factcheck_system 的 `app, scripts, data, static, tmp, README.md, .env*, requirements.txt, Dockerfile, docker-compose.yml, _run_backend.bat` → `code/backend/`。
3. 移除內層套件 + egg-info（＋視決定 alembic）。
4. 刪空的 `factcheck_system/` 殼。
5. 重建 venv：`code/backend/` 下 `python -m venv venv` + `pip install -r requirements.txt`。
