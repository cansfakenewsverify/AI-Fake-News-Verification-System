# 信心程度驗證計畫（草案，2026-10-28）

負責人 2026-10-28：**信心程度是這一輪最重要的項目；驗證後如果沒有鑑別力，就拿掉信心程度這個功能。**
這份文件在跑之前先寫好「怎麼驗」與「過關標準」，避免看了結果才決定標準。
信心程度的現行規則見 `docs/rebuild/信心程度的產生方式.md`（FR-22，`code/backend/app/services/evidence.py`）；
上線後的整體準確率驗證見 `docs/test/上線後準確率驗證計畫.md`（本文件是其中第 4 節「信心分數怎麼評估」的具體執行）。

之後依序做嵌入模型比較與純模型比較（目標 2026-12-03 期末成果展）；嵌入模型比較直接併進本計畫的第 3 步。

## 1. 已知結果：AI 自評分數沒有鑑別力（2026-10-28，零成本）

資料：每週評測 2026-10-19、10-26 兩週的逐題 CSV（`docs/test/results/weekly/`；兩週都是判定校準 v4，即現行系統提示），
排除 AI 服務不可用的列，共 5,221 題（歷史抽樣 5,160、本週新查核 61）。`confidence_score` 是 AI 回答附帶的自評分數。

- 99.7% 的題目自評 ≥ 0.7，92.3% ≥ 0.8，幾乎沒有變化。
- 分數越高並沒有越準：

| AI 判定 | 自評分數 | 題數 | 風險判定正確率（95% 信賴區間） |
|---------|----------|-----:|-------------------------------|
| 有風險（SCAM／MISINFO） | < 0.8 | 292 | 91.1%（87.3%–93.9%） |
| | 0.8～0.9 | 947 | 80.7%（78.0%–83.1%） |
| | ≥ 0.9 | 2,751 | 84.8%（83.5%–86.1%） |
| 安全（SAFE） | 0.8～0.9 | 49 | 59.2%（45.2%–71.8%） |
| | ≥ 0.9 | 177 | 64.4%（57.1%–71.1%） |

- 以自評分數區分「判對／判錯」的 AUROC = **0.53**（3,508 題判對、709 題判錯；判「無法查證」的不計），等於沒有資訊。

影響：

1. 支持 2026-09-23 的決定：網站顯示的「信心 高／中／低」不用 AI 自評分數（FR-22）。
2. 綠燈條件之一 `GREEN_MIN_CONFIDENCE = 0.7`（`app/utils/verdict.py`）讀的仍是自評分數：227 筆 SAFE 判定沒有一筆低於 0.7，
   **這個條件實際上擋不到任何東西**；綠燈真正的把關是「要有 Tier 1／2 查核來源」。是否移除這個條件待負責人決定
   （移除不改變現行行為，只是讓規則表誠實）。

限制：歷史抽樣的題目可能出現在模型訓練資料中；安全題全取自 Cofacts 認可為非謠言的訊息；不經快取、不帶 web_search。

## 2. 要驗證的對象：證據信心（網站顯示的 高／中／低）

現行門檻（相似度 0.65、話術差距 0.10）與話術原型，都是用評測題庫 150 題定的，也只在這 150 題上驗過——
**用同一批題目定門檻又拿來驗，結果一定好看**，這是這一輪要補的缺口。

## 3. 方法

1. **題目**：沿用每週評測已判讀過的題目（判定校準 v4 起約 5,200 題，之後每週再加約 2,600 題）。
   AI 判定已經有了，**不必再花判讀額度**；只需抓回原文（Cofacts、MyGoPen、台灣事實查核中心）並算 embedding。
2. **時間切分**：每一題只能比對「發布日期早於該題」的查核結論（當然也不含自己）。模擬真實情況：新訊息進來時，
   知識庫裡只有更早的查核。知識庫的 `created_at` 都是 2026-09-30 第一次同步的日期，所以發布日期取自抓取語料的 `published`。
3. **定門檻與驗證分開**：依查核網址的雜湊把題目分成開發組與測試組（各半）。門檻與話術原型只用開發組
   （與開發組題目的語料）重算，**報告只列測試組的數字**。
4. **同一份規則表**：直接呼叫 `evidence.assess` 得到每題的等級與依據。規則 5、7（AI 引用的查核來源）無法重現
   （每週評測不存來源、不帶 web_search），報告另外說明。
5. **三種 embedding 各跑一次**（即嵌入模型比較）：`text-embedding-3-small`（現行，1536 維）、`text-embedding-3-large`（3072 維）、
   `bge-m3`（1024 維，CGU 閘道的本地模型）。其他開源模型（bge-large-zh-v1.5、Qwen3-Embedding-0.6B、multilingual-e5-large、
   embeddinggemma-300m）時間夠再加。同時記錄改寫句命中率（PF-2 題組）與檢索速度。
6. 報告寫到 `docs/test/results/confidence_validation_<日期>.md`，**不存訊息原文**（Cofacts 訊息可能含個資；repo 是公開的），
   只存查核網址、雜湊與判定。

## 4. 過關標準（草案，待負責人確認；跑之前定案）

以測試組計算；**任一種 embedding 四項全部達成就算過關**，並改用那一種 embedding。

| # | 指標 | 標準 | 為什麼 |
|---|------|------|--------|
| 1 | AI 判有風險的題目中，「中」的正確率 | ≥ 90%，且高於同樣判有風險但只拿到「低」（只有 AI 判斷）的題目，兩者 95% 信賴區間不重疊 | 「中」要真的比「低」可靠，使用者看到的差別才有意義 |
| 2 | 「高」：最近的已查核案例相似度 ≥ 0.75（網站會直接沿用該案例的結論）時，結論與真值一致的比例 | ≥ 95% | 「高」代表「查核機構查過同一則」，不能常常對錯人 |
| 3 | 衝突提醒（AI 判安全、但附近有已查核的不實內容）中真的有風險的比例 | ≥ 沒有提醒的安全判定的 2 倍 | 提醒要真的抓得到漏判 |
| 4 | AI 判有風險的題目中拿到「中」以上的比例 | ≥ 20% | 否則幾乎全是「低」，等級沒有資訊量 |

## 5. 沒過關時

依序考慮（第 1 項還是要重新驗證標準 1）：

1. 把「高／中／低」改成兩種事實陳述：「有已查核的相近案例支持」／「只有 AI 判斷」——不宣稱機率，只說有沒有證據。
2. **拿掉「信心」標示，保留「知識庫中的相似查證」清單與衝突提醒**：那是可以點開查證的證據，不是信心宣稱。
   不建議連相似查證一起拿掉。

## 6. 執行需要

- 雲端 session 的環境變數 `CGU_API_KEY`（不要貼在聊天或任何檔案裡）。
- 網路允許的網域：`air.cgu.edu.tw`、`www.mygopen.com`、`tfc-taiwan.org.tw`、`api.cofacts.tw`、`cofacts.tw`
  （2026-10-28 這幾個網域都被雲端環境的網路政策擋下）。
- 花費：不需要新的 AI 判讀。embedding：small 約 USD 0.25（2026-09-23 全量實扣 0.24）、large 約 USD 1.6（以 small 實扣的 6.5 倍估算）、
  bge-m3 不花 OpenAI 額度。跑在週四額度重置後，避開週日的每週評測。
