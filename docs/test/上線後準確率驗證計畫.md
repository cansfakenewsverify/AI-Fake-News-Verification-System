# 上線後準確率驗證計畫

（2026-09-23 初版；2026-09-30 增補 M5 每週新查核自動評測，並依模型更換更新成本。
適用於系統上線後的持續量測，與報告前的一次性驗收測試 `docs/test/TP-FNV-2026-01.md` 並行；
本計畫的結果回填測試計畫書第 6 節。）

## 1. 為什麼另外需要這份計畫

報告前的品質測試 QA-1a／QA-1b 以 `data/eval_set.csv` 的 150 筆量測，
2026-09-16 的結果為 accuracy 100%、macro-F1 1.000、FN=0、FP=0。
這個數字**不能當成上線後的準確率**，原因有三：

1. **題庫已飽和**：150 筆全對代表題目對現行模型太簡單，分不出設定或模型之間的差異，
   也量不到系統真正會出錯的地方。
2. **題庫是公開的**：`eval_set.csv` 自 2026-06 起就放在公開的版本庫裡，
   無法排除模型在訓練階段看過題目。
3. **題目不是真實流量**：題目由團隊自行設計，句型與長度分布和使用者實際貼進來的內容不同。

因此本計畫定義五種並行的量測方法、各自的真值來源與判定準則，
以及信心分數的校準方式，作為「上線後系統到底準不準」的證據。

## 2. 名詞定義

| 名詞 | 定義 |
|------|------|
| 真值（gold） | 由人工依查核機構已發布的結論判定的正確分類，值為 `SCAM`／`MISINFO`／`SAFE`／`UNVERIFIABLE` |
| 正確 | 系統的 `risk_type` 與真值相同 |
| 偽陰性（FN） | 真值為 `SCAM` 或 `MISINFO`，系統卻判為 `SAFE`。這是本系統唯一的絕對禁止項 |
| 偽陽性（FP） | 真值為 `SAFE`，系統卻判為 `SCAM` 或 `MISINFO` |
| 有效預測 | 非 fallback（`ai_unavailable` 為真者不計入分母，另列「服務不可用率」） |
| 綠燈精確率 | 所有顯示綠燈的結果中，真值確實為 `SAFE` 的比率。這是使用者真正承受的風險，比整體 accuracy 更重要 |

`UNVERIFIABLE` 於計算 accuracy 時單獨列一類，不與 `SAFE` 合併；
爬不到內容而回 `UNVERIFIABLE` 屬系統正確行為，不計為判錯。

## 3. 五種量測方法

| 代號 | 方法 | 真值來源 | 量到什麼 | 成本 |
|------|------|----------|----------|------|
| M1 | 封閉題庫評測 | 查核機構已發布的結論 | 分類正確率、FN、FP、混淆矩陣 | 每次約 USD 0.13（90 題） |
| M2 | 線上結果抽樣人工覆核 | 兩名組員獨立判定 | 真實流量上的正確率與誤解樣態 | 無 AI 成本，人工每週約 40 分鐘 |
| M3 | 查核結論回溯比對 | 查核機構事後發布的結論 | 當時判錯而後來被查核推翻的比率 | 僅 embedding |
| M4 | 使用者回饋 | 使用者點選的同意／不同意 | 弱訊號，用於挑出要覆核的樣本 | 無 |
| M5 | 每週新查核自動評測 | 查核機構當週發布的結論 | 模型沒看過的真實謠言上的判讀正確率與偽陰性；歷史輪替累積整個知識庫的正確率 | 每週用剩的 CGU 額度（上限 USD 6，保留 USD 3） |

### M1 封閉題庫評測（主要數字）

- **題目來源**：報告日之後才發布的查核文章（MyGoPen、台灣事實查核中心、Cofacts 已有 RUMOR 回覆者），
  以及同期的政府公告、銀行與電信公司的正式通知（作為 `SAFE` 題）。
- **題數與配比**：90 題，`SCAM`／`MISINFO`／`SAFE` 各 30 題。90 題在「零判錯」時，
  以三的法則估計錯誤率的 95% 上界為 3.3%，足以支撐「錯誤率低於 5%」的敘述；
  若要把正確率的信賴區間收到 ±5%，需要約 140 題，視額度再決定是否擴充。
- **不公開**：題目原文與標籤**不進版本庫**，只把每題的 SHA-256 與標籤存進版本庫作為存證，
  原文另存於負責人的雲端硬碟。這是為了避免重蹈 `eval_set.csv` 被公開的問題。
- **出題人**：由非實作組員（姚睿）出題與標註，AI 助理不得代為產生題目（同票 O-11 的原則）。
- **執行**：`scripts/evaluate.py --delay 0`（`USE_WEB_SEARCH=false`），
  輸出 `eval_predictions.csv`（含 `provider`／`model`／`date`／`use_web_search`／`elapsed_ms` 欄）
  與 `eval_report.csv`；判錯案例在 `eval_errors.csv`，逐筆有 `error_type`。
- **頻率**：換模型、改系統提示、改門檻時各跑一次；其餘每月一次。
- **重要限制**：執行時**不要**加 `--seed-db`，否則題目會以 `gold` 標記寫進知識庫，
  下一輪就會在快取層命中，題庫等於作廢。

### M2 線上結果抽樣人工覆核（真實流量的數字）

- **抽樣**：每週從 `tasks` 表中抽 20 筆，分層抽樣——紅燈、黃燈、綠燈各取一定比例，
  並且必須包含當週所有被使用者標記為「不同意」的結果（見 M4）。
- **覆核**：由兩名組員**各自獨立**判定真值，不先看系統判定；
  兩人不一致的題目由第三人裁定，並計算 Cohen's kappa 作為標註一致性的證據
  （kappa < 0.6 表示判定準則本身不夠明確，要先修準則再繼續）。
- **記錄**：`docs/test/results/live_audit_YYYY-MM-DD.csv`，
  欄位為 `task_id`、`frame_type`、`risk_type`、`confidence`、`cache_layer`、
  `gold_a`、`gold_b`、`gold_final`、`correct`、`note`。
- **快取命中的處理**：`cache_layer` 不是空值的結果，判定來自先前的那一次 AI 判讀，
  要分開統計；語意層命中（vector）另外記錄「是否真的是同一則訊息」，
  這同時是第二層快取誤命中率的量測。

### M3 查核結論回溯比對（事後真值，成本最低）

`scripts/recheck_unverified.py`（唯讀）本來就會把知識庫中「尚無查核機構證實」的資料，
與後來寫入的查核機構結論比對。把它的輸出當成回溯驗證：
凡是當初系統判為 `SAFE`、後來被查核機構認定為不實的內容，都是一筆真實世界裡的偽陰性。

- **頻率**：每月一次，在查核結論同步（GitHub Actions `factcheck-sync`，每天兩次）開始運作之後才有意義。
- **判定**：只要出現一筆，就必須登錄為缺陷並做錯誤分析，不因為「只有一筆」而略過。

### M4 使用者回饋（只作為抽樣導引，不直接當正確率）

`POST /api/feedback/tasks/{id}` 收到的 `rating` 是使用者的主觀意見，
不是真值——使用者可能誤解判定、也可能不同意正確的結論。
因此回饋**只用來決定哪些結果要進 M2 的人工覆核**，
另外統計「不同意率」作為趨勢指標，不寫成準確率。

### M5 每週新查核自動評測（自動、每週一次）

CGU 的 OpenAI 額度每週 USD 10、用不完不累積。M5 把每週剩下的額度拿來做評測，
全程自動（`app/services/weekly_eval.py`，GitHub Actions `weekly-eval` 每週日 21:17 執行，規格 FR-24）：

- **題目與真值**：全部來自查核機構已發布的結論，不由 AI 助理或組員產生（與 M1 的出題原則一致）。
  - 本週新查核（主要數字）：最近 7 天發布、已有判定的查核結論——MyGoPen 標題標籤、
    台灣事實查核中心「查核結果」、Cofacts 獲認可的回覆；含查核結果為真的 SAFE 題。一篇報告一題。
    這些內容出現在模型訓練之後，不會有「模型看過題目」的問題。
  - 歷史輪替（參考）：知識庫中查核機構已證實的訊息依固定順序每週往下取 2,000 題，
    約 9～10 週輪完 1.85 萬筆，累積起來就是整個知識庫的判讀正確率；另以 Cofacts 認可為非謠言的訊息當安全題（2:1）。
    可能出現在模型訓練資料中，數字偏樂觀，報告分開列。
- **執行條件**：直接呼叫 AI（不經快取、不帶 web_search、不寫知識庫），量的是 AI 判讀本身。
  網站上的燈號另外要求查核來源，所以使用者看到的綠燈比這裡的 SAFE 更保守。
- **額度護欄**：本次可用 = min(USD 6, CGU 剩餘 − USD 3)；每 100 題重讀一次 CGU 用量，快碰到保留額就停；
  讀不到用量時只跑本週新查核且上限 USD 1。保留的 USD 3 以現行模型約可支應 2,000 次使用者查證，
  超過每日上限 300 次 × 7 天。
- **紀錄**：報告與逐題 CSV 自動存進 `docs/test/results/weekly/weekly_eval_YYYY-MM-DD.{md,csv}`；
  不存訊息原文（Cofacts 訊息可能含個資），只有查核網址、雜湊、真值與 AI 判定。
- **解讀**：
  1. 主要數字為「風險判定一致率」：Cofacts 的 RUMOR 一律記為 MISINFO，其中的詐騙訊息被判為 SCAM 算正確。
  2. Cofacts 的題目是使用者回報的原始訊息，常是詐騙對話中的一句，單看一句本來就難以判斷；
     MyGoPen 與台灣事實查核中心的題目是查核機構整理過的主張。報告依來源分列，兩者要分開看。
  3. 偽陰性每一筆都要打開查核網址確認：查核機構文章的偽陰性依第 5 節做錯誤分析；
     Cofacts 的對話片段若單看該句確實無法判斷，在覆核紀錄註明後不列為缺陷。
- **換模型時的比較**：M5 的本週題目也是換模型時最好的比較組。2026-09-30 閘道下架 `gpt-5.4-mini` 後，
  即以當週 41 則新查核比較兩個候選模型（`docs/test/results/model_switch_2026-09-30.md`）。

## 4. 信心分數怎麼評估

（2026-09-23 起，結果頁顯示的「信心 高／中／低」改依證據決定，不再由 `confidence_score` 換算，
見 `docs/rebuild/信心程度的產生方式.md`；本節量測 M1、M2 樣本時兩者都要記錄，比較哪一個校準得較好。）

系統的 `confidence_score` 目前只有一個地方會影響使用者看到的東西：
`app/utils/verdict.py` 的 `GREEN_MIN_CONFIDENCE = 0.7`——
`SAFE` 且已證實且信心 ≥ 0.7 才給綠燈，否則是黃燈。
所以信心分數要驗的不是「數字好不好看」，而是**這個門檻擋得住多少錯誤**。

以 M1 與 M2 累積的樣本計算三項：

1. **可靠度圖與 ECE**：把信心分數切成 0.5–0.6、0.6–0.7、0.7–0.8、0.8–0.9、0.9–1.0 五段，
   每段計算實際正確率，對照該段的平均信心。期望校準誤差（ECE）＝各段樣本數加權的差距絕對值。
   模型若一律回報 0.9 以上，ECE 會直接顯示這件事，代表信心分數沒有鑑別力。
2. **Brier score**：以「是否為風險訊息」的二元機率計算，用於跨版本比較。
3. **門檻的實際效果**：計算綠燈精確率，以及「若把門檻改為 0.6 或 0.8，綠燈精確率與綠燈涵蓋率各變成多少」。
   門檻只有在這張表上看得出代價時才調整，不憑感覺改。

**要先確認的前提**：若模型回報的信心集中在少數幾個值（例如幾乎都是 0.9），
則 0.7 這個門檻實際上沒有在過濾任何東西，應在報告中據實說明，
並改以「是否有 Tier 1／2 查核來源」作為綠燈的主要條件——這一條在 `frame_of()` 中已經是前提，
信心門檻只是附加條件。

## 5. 判定準則

| 項目 | 準則 | 未達標的處置 |
|------|------|--------------|
| FN（絕對條件） | M1 與 M3 皆為 0 | 任一筆即停止對外宣稱可用，做錯誤分析並修正提示或規則後重跑 |
| M1 accuracy | ≥ 90%，附 Wilson 95% 信賴區間 | 記錄實際值與錯誤分析，不擋既有功能 |
| M2 真實流量正確率 | ≥ 85%（真實內容較雜，準則低於題庫） | 同上，並檢查是否集中於某一類輸入 |
| 綠燈精確率 | ≥ 95% | 檢討綠燈條件（來源門檻優先於信心門檻） |
| 標註一致性 | Cohen's kappa ≥ 0.6 | 先修訂判定準則再重新標註 |
| 服務不可用率 | fallback 占比 < 5% | 查 AI 服務與每日上限，見 CLAUDE.md 第 2 節 |

所有對外呈現的數字都要同時標示 provider、model、日期、樣本數與信賴區間；
不得只寫一個百分比。

## 6. 分工、頻率與成本

| 工作 | 負責 | 頻率 | 成本 |
|------|------|------|------|
| M1 出題與標註 | 姚睿（績效與品質數據） | 建立一次，之後每季補題 | 人工 |
| M1 執行與報告 | 廖晢勛（測試負責人） | 每月，或換模型時 | 每次約 USD 0.6 |
| M2 抽樣與覆核 | 石岱勳、張宇宏（獨立標註） | 每週 | 人工約 40 分鐘 |
| M3 回溯比對 | 廖晢勛 | 每月 | 僅 embedding |
| M4 統計 | 姚睿 | 每月 | 無 |
| M5 報告檢閱與偽陰性確認 | 廖晢勛 | 每週（自動產生報告後） | 每週用剩的 CGU 額度 |
| 結果彙整與簽核 | 廖晢勛 彙整、張宇宏 覆核 | 每月 | 無 |

CGU 閘道的額度為 OpenAI 成本每週 USD 10（用不完不累積）。2026-09-30 起的模型 `gpt-5.6-luna`
每次未命中快取的查證約 USD 0.0014（之前的 `gpt-5.4-mini` 約 USD 0.0064）。
M1 每次 90 題約 USD 0.13；M5 每週自動使用剩下的額度，並保留 USD 3 給網站使用者。
執行前後各查一次 `GET {CGU_BASE_URL}/me/usage` 並記錄。

## 8. 已知限制（對外一併說明）

1. 本計畫的真值仍來自查核機構的結論，查核機構沒查過的主題就沒有真值，
   這類內容只能停在「尚無查核機構證實」，不計入正確率。
2. M2 的樣本量小（每週 20 筆），單週的數字波動大，只有累積數月才有意義。
3. 判定為 `SAFE` 的內容是否真的安全，本質上無法完全驗證——
   沒有證據證明某則訊息為假，不等於它為真。因此系統的綠燈定義為「查無異常」而非「保證真實」。
4. 所有量測仍由團隊執行；第三方實測（`docs/rebuild/HANDOFF.md` 待辦第 4 項）另行規劃，
   兩者互補：本計畫量的是判定準不準，第三方實測量的是使用者用不用得起來。
