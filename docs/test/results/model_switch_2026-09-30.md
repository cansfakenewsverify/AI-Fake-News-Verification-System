# AI 模型下架與改用新模型（2026-09-30）

## 發生了什麼

- 2026-09-30 以真的閘道試跑「每週新查核自動評測」（規格 FR-24）時，每一次判讀都回
  HTTP 404：`Model 'gpt-5.4-mini' is not available on this gateway`（`model_not_found`）。
- CGU AIR 閘道的模型清單（`GET {CGU_BASE_URL}/models`）已經沒有 `gpt-5.4-mini`；
  可用的對話模型為 `gpt-5.6-luna`、`gpt-6-luna` 與本地的 `gpt-oss:20b`，embedding 的 `text-embedding-3-small` 仍在。
- **影響**：正式站所有沒命中快取的查證都回灰色的「AI 分析暫時無法使用」（fallback）；快取命中、熱門牆、知識庫不受影響。
  `/api/health` 的 `ai_available` 只代表金鑰有設，仍顯示 `true`，所以沒有人發現。開始時間不明
  （當天正式站的每日 AI 次數為 0）。
- 測試計畫書登錄為 DEF-10（`docs/test/TP-FNV-2026-01.md` 6.7）。

## 候選模型比較

兩個候選模型各跑一次同一批題目：系統提示、推理強度 `medium`、不帶 web_search，與正式站相同；並行 4 個請求。
花費以 CGU `/me/usage` 執行前後的差計算。

| 題組 | 指標 | `gpt-5.6-luna` | `gpt-6-luna` |
|------|------|---------------:|-------------:|
| 評測題庫 150 題（`data/eval_set.csv`） | 三類一致率 | 98.7% | 99.3% |
| | 偽陰性（有風險判成安全） | **0** | **0** |
| | 偽陽性（安全判成有風險） | 2 | 1 |
| 本週新查核 41 則（2026-09-23～09-30 發布） | 風險判定一致率 | **87.8%** | 75.6% |
| | 偽陰性 | **5** | 10 |
| | MyGoPen／台灣事實查核中心／Cofacts 風險判定一致 | 7/7、6/7、23/27 | 4/7、6/7、21/27 |
| 成本 | 每次呼叫 | USD 0.00144 | USD 0.00071 |
| 延遲 | p50／p90（150 題） | 5.1 s／7.6 s | 5.2 s／8.1 s |

**選擇 `gpt-5.6-luna` 為主模型、`gpt-6-luna` 為備援**：

- 評測題庫已飽和（兩者都接近全對、偽陰性都是 0），分不出高下；
  模型沒看過的本週新查核才看得出差異——`gpt-6-luna` 漏判 10 則，其中 3 則是 MyGoPen 整理過的明確謠言
  （垃圾、台電、法規三篇），`gpt-5.6-luna` 在 MyGoPen 全對。偽陰性是本系統唯一的絕對禁止項，所以選漏判較少者。
- `gpt-5.6-luna` 每次約 USD 0.0014，是舊模型 `gpt-5.4-mini`（約 USD 0.0064）的 22%；每週 USD 10 的額度約可支應 7,000 次判讀。
- 本週新查核的 27 則 Cofacts 題多為詐騙對話中的一句（例如「你今天有時間去辦理一下預付卡嗎」），
  單看一句本來就難以判斷。`gpt-5.6-luna` 的 5 則漏判：3 則是這類短句（貸款照會、辦預付卡、辦電話卡）；
  1 則是投資群組的推薦訊息（典型的投資詐騙開場，應該判出來）；1 則是台灣事實查核中心的
  「川普親吻女子照片為 AI 生成」（純文字看不出是圖片造假）。
- 限制：本週新查核只有 41 則且只跑一次；之後每週的 `weekly-eval` 報告會持續累積同一模型的數字。
  圖片判讀（`/api/analyze/image`，網頁尚未開放上傳）沒有以新模型測試。

## 正式評測（`scripts/evaluate.py --timing --delay 0`）

以新模型依序重跑 150 題（與歷次評測相同的程序；未加 `--seed-db`），結果寫進 `code/backend/data/eval_*.csv` 與 `assets/confusion_matrix.png`：

| 指標 | `gpt-5.6-luna`（2026-09-30） | `gpt-5.4-mini`（2026-09-16，已下架） |
|------|---------------------------:|----------------------------------:|
| Accuracy | 96.7%（95% CI 92.4%–98.6%） | 100% |
| Macro-F1 | 0.967 | 1.000 |
| 偽陰性 FN | **0** | 0 |
| 偽陽性 FP | 5 | 0 |
| 未命中延遲 p50／p90 | 5.87 s／8.31 s | 4.86 s／6.64 s |

- 5 筆偽陽性全是 SAFE 題中的官方公告（綜所稅申報期間、基本工資審議、故宮開放時間、高溫假指引、節能補助），被判為 MISINFO；
  上面並行比較時同一模型只錯 2 筆，這一類題目的結果會浮動。這類誤判在網站上顯示為紅燈「假訊息」，是使用者看得到的誤報，
  列入每週評測持續觀察（本週新查核的 SAFE 題很少，偽陽性主要靠歷史輪替的安全題量測）。
- 與舊模型逐題比較：5 筆由對變錯、0 筆由錯變對，McNemar 精確檢定 p = 0.0625（未達 0.05）。
- 測試計畫書 QA-1a（FN = 0）與 QA-1b（accuracy ≥ 93%、FP ≤ 8）皆達成；PF-1（未命中 p50 ≤ 15 s、p90 < 20 s）達成。

## 程式與設定的變更

- `CGU_MODEL` 預設改為 `gpt-5.6-luna`，新增 `CGU_FALLBACK_MODEL`（預設 `gpt-6-luna`）；`render.yaml` 明列兩者，不再依賴程式預設值。
- `ai_service._cgu_analyze`：閘道回 404 `model_not_found` 時改用備援模型再試一次；金鑰、額度、限流等其他錯誤不換模型。
- `ai_service.gateway_models()`：讀閘道模型清單（不花額度）。查核結論同步（FR-23）每次執行都檢查
  `CGU_MODEL`、`CGU_FALLBACK_MODEL`、`EMBED_MODEL` 是否還在，不在時 GitHub Actions `factcheck-sync` 變紅並寄信。
- 舊模型的評測結果封存在 `code/backend/data/eval_archive_gpt54mini_2026-09/`。

逐題資料（含題目原文）未進版本庫：比較用的預測檔在負責人電腦的暫存資料夾；正式評測的逐題結果在 `code/backend/data/eval_predictions.csv`。
