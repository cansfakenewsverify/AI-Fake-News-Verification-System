# UI-1 介面檢核作業說明

測試計畫書 TP-FNV-2026-01 的 UI-1 要求介面逐格檢核，並由**非實作組員**勾核、另一位組員覆核，
以避免實作者檢查自己的作品。本文件說明該項檢核的執行方式。

- 勾核：石岱勳（組員 B，介面測試）
- 覆核：張宇宏（組員 D，文件與審查）
- 檢核表：`docs/test/ui_checklist.csv`（UTF-8 BOM，可直接以試算表軟體開啟）
- 截圖：`docs/test/screens/`

## 檢核表結構

檢核表共 143 列，一列對應一張截圖：淺色 77 列、深色 63 列，另 3 列涵蓋兩種主題。
欄位如下：

| 欄位 | 內容 |
|------|------|
| `ID`、`screen`、`state`、`width`、`theme`、`file` | 該格對應的畫面、狀態、寬度、主題與截圖檔名 |
| `result`、`note` | 擷取當下的自動檢查結果與紀錄。淺色列另含擷取時的目視預檢，深色列留空 |
| `勾核者`、`勾核結果`、`勾核日期` | 由勾核者填寫，結果為「通過」或「不通過」 |
| `覆核者`、`覆核結果` | 由覆核者填寫 |

`result` 欄為擷取時的自動檢查與預檢紀錄，保留作為對照；UI-1 的判定以 `勾核結果` 欄為準。

## 判定準則

逐列開啟 `file` 欄指向的截圖，確認畫面、狀態、寬度與主題與該列相符，再依下列四點判定，
四點皆符合者記為通過：

1. 文案與規格書 `docs/rebuild/01_spec.md` §8.7 的文案表一致（錯字、多字、少字皆不通過）。
2. 無 §8.6 列出的違規：字級小於 13 px、僅於滑鼠移入時才顯示的說明。
3. 紅黃綠三色僅出現於判定相關元素（判定塊、燈號、判定標籤）；導覽列、按鈕與一般文字不得使用。
4. S1 首頁與 S2 結果頁另與設計稿對照（`docs/rebuild/mockup/Main.dc.html`、`Result.dc.html`、
   `ResultStates.dc.html`）；S3、S4、S6 則對照規格書 §8.3 的元件清單。

記為不通過者，於該列 `note` 欄末尾追加說明，原有內容保留；同一問題重複出現時，
第一列寫明原因，其餘列註記「同 UI-1-0xx」。

## 截圖的產生方式

深色版 54 張由 `code/frontend/tools/capture_ui.mjs` 擷取：以無頭瀏覽器逐一佈置 S1–S4 的各個狀態
並全頁截圖，每個 `/api/*` 請求由腳本以 CDP 直接回應，回應內容取自 `code/frontend/src/dev/fixtures`
的同一批 JSON，另加上檔案無法表達的延遲（載入中）與連線失敗（連不上後端）。
過程不連線後端、不存取資料庫、不呼叫 AI。

每張截圖存檔前均由程式確認畫面確實出現該狀態的關鍵字，逐張紀錄見
`docs/test/screens/shots_dark.json`，檢核表各列的 `note` 欄亦記載該張截圖的產生方式。

## 完成後

勾核與覆核皆填妥後，結果彙整至測試計畫書第 6 節，UI-1 始得結案。
